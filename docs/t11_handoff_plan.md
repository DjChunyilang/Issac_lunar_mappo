`run_upstream_t11.py --mode signal --authorize-signal100k`消费该准入。启动器与底层更新器同时支持该范围。原`--mode train`完整验收路径保留，不能用signal准入冒充通过或扩大预算。

顺序入口`run_upstream_t11_signal_suite.py`依次执行A1→A0→A2→A3，各自独立run；前组完成100k后再启动下一组。出现运行错误保留现场并停止队列，不静默跳过该方案或覆盖结果。完整运行命令见[运行手册](runbooks/t11_training_handoff.md)。

## 首批观察与恢复

直接使用真实训练的首批数据观察，不另加大型测试：

1. 每16宏步记录有效比例、观测/概率有限性、HOLD比例、实际下发速度、位置和任务状态。
2. 每128宏步完成5轮PPO，保存loss、梯度、ratio、KL、clip、优势/回报分布和有效转移数。
3. 保存原始动作/概率、执行反馈、结束原因、奖励分量和每次更新后的环境/GRU/优化器/RNG状态。
4. 分开检查“有效样本”“参数实际更新”“MOVE实际推进”“HOLD实际停车”。若动作无执行效果、反复拒绝或学习数值异常，依据真实记录定位，不据单次零成功直接淘汰方案。

本阶段关闭自动插入的每10次更新/阶段末18场景完整评测，将计算用于学习信号；18场景独立比较保留为后续单独安排，不插在A1之前，也不阻塞四组首次信号收集。未经独立比较不得宣布某组最佳或Gate C通过。
