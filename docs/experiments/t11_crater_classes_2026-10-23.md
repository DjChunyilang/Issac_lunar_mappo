# 坑按大小通行：实现与短程验证

2026-10-23。**已实现“小坑不罚、中坑轻罚、大坑禁入”，并通过针对性检查和真实地图短测。** 小中坑不再因旧的坑壁坡度、台阶和“触底”几何检查而导致驾驶失败。停车仍检查原始地面，岩石规则保留。

本轮共 **1,168／2,000 个实际底层步，0 次学习更新**，验证的是规则是否生效、能否接入现有规划执行链。整体奖励中“提前失败可能比长期安全行驶得分高”的问题，仍按[奖励审计](t11_reward_audit_2026-10-23.md)单独处理。

## 1. 阈值依据与地图分布

车辆长 5.015 m、宽 3.2 m，车轮半径 0.5 m、轮距 1.8 m、轴距 2.7 m。当前模型只计算平面位置、朝向和速度，没有车轮接触、悬架或整车俯仰动力学。因此，下面是**首轮 Proxy 任务假设**，并非物理通过能力的测量结果。

| 坑口直径 D | 驾驶规则 | 阈值含义 |
| --- | --- | --- |
| D < 0.5 m | 忽略坑造成的风险、代价和奖励扣分 | 暂以一个轮半径作为小坑上限，替换此前未经核对的 1 m 候选值 |
| 0.5 m ≤ D < 1.8 m | 可以通过，轻微扣分 | 平面模型不模拟下坑／爬坑，通过性由任务规则指定 |
| D ≥ 1.8 m | 车身实际投影侵入坑口即失败 | 以当前轮距作为候选分界，并结合地图频次；不代表达到轮距就必然物理失效 |

四张地图的坑径均为 0.8–2 m，坑深约 0.064–0.16 m。因此实际地图里**没有小坑，约 95% 为可通过中坑，约 5% 为禁入大坑**；小坑行为用合成场景验证。以下按坑中心位于目标地图内计数：

| 地图 | 小坑 | 中坑 | 大坑 | 大坑比例 |
| --- | ---: | ---: | ---: | ---: |
| train_0 | 0 | 35,420 | 1,672 | 4.51% |
| train_1 | 0 | 35,355 | 1,715 | 4.63% |
| fixed_eval | 0 | 35,224 | 1,802 | 4.87% |
| unseen | 0 | 35,437 | 1,652 | 4.45% |

如果大坑分界设为 1.2 m，约 34–35% 的坑会禁入；设为 1.5 m 则约 15%。选 1.8 m 意味着主要保留尺寸分布尾部作为障碍。原始统计和场景指纹见 run 内 `metrics/threshold_distribution.json`。

## 2. 实际改变了什么

驾驶使用单独生成的地形数据：保留底图、岩石和分形起伏，去除合成坑层；坑的影响统一交给分档标签处理。这样，小中坑不会通过旧的坡度、粗糙度、台阶、离地间隙或地形速度系数再次被罚。原始地图文件不变，停车和驻留仍使用原始含坑地面。底图或岩石本身不满足原有驾驶条件时，仍可失败。

中坑规划代价系数为 0.5／秒，奖励扣分系数为 0.05／秒。奖励按四车平均侵入程度折算：一辆车完全覆盖中坑时，团队每秒最多扣 0.0125 分，四辆都覆盖时最多扣 0.05 分；每回合累计最多扣 2 分。该账本随回合重置、随状态保存恢复，中坑不触发失败。

中坑软代价使用已有保守车体覆盖计算，所以车身靠近坑口时可能已出现轻罚。**大坑实际失败边界单独采用精确车身矩形与坑口圆相交，不加 0.3 m 安全余量；仅相切不判侵入。** 每个 0.2 s 执行步检查实际位姿。规划器可以提前留出余量，但只使用已感知标签，不读取全图真值；最终候选复核也会拒绝已知大坑。

大坑侵入沿用 `terrain_failure` 结束回合，并记录 `large_crater` 子原因。本轮沿用正式训练的失败系数 100，故终端项为 −100；这个系数来自奖励配置。岩石和其他任务失败保持原义。出生筛选也已接入分档规则，避免驾驶允许中坑、出生却仍按旧坑壁条件拒绝。

## 3. 验证结果

单坑直行测试给定前进命令，经过现有执行、感知、地形判定和奖励链。其余三车停在场景内，扣分为团队数值；这项测试不代表策略自主选路。

| 场景 | 新规则结果 | 关键观测 |
| --- | --- | --- |
| 0.4 m 小坑 | 完整穿过 | 坑相关扣分为 0，地形扣分与平地一致 |
| 1.2 m 中坑 | 完整穿过 | 中坑累计扣分约 0.149，无地形／原障碍重叠扣分 |
| 1.9 m 大坑 | 侵入后失败 | `large_crater`，终端项 −100；侵入前一个执行步未失败 |
| 岩石 | 失败规则保留 | 新旧同样触发地形失败，终端项 −100 |
| 中坑上停车 | 保留原限制 | 同位姿新旧停车检查相同，该例因停车坡度不合格而拒绝 |

旧规则下同一个 1.2 m 中坑没有直接导致失败，但产生约 −7.33 的障碍重叠扣分、额外地形扣分和减速；新版将其改成轻罚。不能把旧版这个案例描述成“中坑必然失败”。

另用真实 `fixed_eval` 图及原最终评估起点，旧版、新版各运行 50 步（10 s）。固定 MOVE 目标、真实 MPPI 64 个候选／两轮更新，seed 23，不加载策略网络：

| 指标 | 旧版 | 分档新版 |
| --- | --- | --- |
| 是否失败 | 否 | 否 |
| 四车净位移（m） | 3.17 / 4.63 / 4.15 / 4.32 | 5.42 / 4.73 / 4.11 / 4.34 |
| 已激活计划记录 | 188 次均有效 | 188 次均有效 |
| 障碍重叠累计扣分 | −15.98 | 0 |
| 中坑累计扣分 | 无此项 | −0.410 |

这说明新链路能在真实地图上规划和运动；净位移不等于向集合目标靠拢。合成场景的两组 MPPI 测试没有前进，也保留了结果：一次不推进环境的诊断显示，64 个候选均通过地形及大坑检查，却全部被邻车预测安全约束拒绝。本轮不据此宣称已验证自主绕大坑。

**72 项不同的针对性测试通过，另有 13 项场景验收通过。** 覆盖阈值边界、旋转车身相交、CPU／CUDA 格查询、未见区域不泄露、规划与最终复核、中坑奖励上限／恢复、驾驶与停车分离、出生筛选及旧版行为。首次测试中的两处夹具断言失败日志保留：一处把地图边缘的合法 NaN 纳入最大值，一处用过缓坑壁却预期旧出生规则拒绝；修正夹具后相关检查通过。
