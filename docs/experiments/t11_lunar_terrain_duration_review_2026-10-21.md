## 1. 为什么上一版是平地，现改为什么

上一版沿用了正式v2的平地环境，目的是保持原学习设置、隔离课程变化。但用户要求的是完整月面任务，把平地继续作为正式候选没有对齐这一目标。现在明确改为现有地图主线：**真实月面DEM＋NASA模型坑石增强，通过`lunar_scene_pack`进入原感知／执行链**；不使用`flat_proxy`，也不把纯随机起伏称作真实月面。

遵循[既有月面地图主线](../architecture/lunar_map_mainline.md)。真实DEM提供大尺度地形；亚米／米尺度坑石属于有来源的工程假设层。保留真实水平尺度、相对高差、缺测掩码和数据来源；不把未知补成平地，不压平或稀释坑石以迎合车辆约束。Actor仍只能读取合法本地传感与通信，地图全局真值不进入Actor。

有两个具体接入缺口必须处理，不能只改一个地形名称：

1. `evaluate_upstream_gathering.terrain_for('npb',...)`当前引用的是**200×200 m**旧开发样例。把世界边界改为1 km不会扩展该地图；R200–300 m出生会超出有效地形。新场景必须来自1 km真实窗口，`scene_manifests`未生成前保持为空且禁止回退。
2. .1 m网格的1 km地图为1亿像元。当前`SceneBank`8个float32通道单张约**2.98 GiB**，超过默认1.5 GiB缓存；四owner各自整图缓存合计约11.92 GiB，尚未包含训练状态和生成临时数组。需在既有场景生成／缓存内做有界处理或共享，保持地形语义；不能直接整图载入并假设能够运行。现有最小特征要求至少5个网格，.6 m岩石不能随意改用.2 m网格。

按1010×1010 m全有效生成面积估算，约37,813个坑、893块石，实际数量还受合法生成中心面积影响；旧`max_features=10000`会拒绝构建。因此提案显式提高资源上限至50,000，保留原分布。此处没有执行地图生成或借此增加独立系统。

## 3. 1200秒是否足够

**结论：不能认定1200秒足够，月面远距场景中明显偏紧；改为3600秒的审计候选较合理，但仍须由新地图上的执行数据校准。** 1200秒只是原课程最远组的既有时限，没有被完整月面可达性结果证明。

证据一是历史实际速度，而非2.78 m/s物理顶速。读取上一轮完整1200s远距平地评估，四例随机执行的平均实际速度为 **.209–.216 m/s**，均值执行为 **.205–.279 m/s**。多数单车累计路程约200–380 m；两种执行均0/4成功。均值策略四例的最大车距全部扩大，说明部分失败来自走错方向，不能归因于时间不足，更不能假定延长时间会自动成功。

证据二是距离和任务耗时。以最远车约300 m的有效靠拢距离作尺度，设绕行路径倍率1.3，并为转向、找可停车区域、末端协调和驻留暂留120 s：

```text
估计时间 = 300 m × 1.3 / 平均实际路径速度 + 120 s
```

| 平均实际路径速度 | 估计时间 | 1200s是否覆盖这个算例 |
|---:|---:|---|
| .30 m/s | 1420 s，23.7 min | 否 |
| .25 m/s | 1680 s，28.0 min | 否 |
| .20 m/s | 2070 s，34.5 min | 否 |
| .15 m/s | 2720 s，45.3 min | 否 |
| .10 m/s | 4020 s，67.0 min | 否 |

1.3倍绕行与120s余量是**估算假设，不是已测月面数据**。实际停车地点也不一定在初始中心，可能进一步增加行程。现有地形执行增益位于[.25,1]，并有行驶／停车地形硬限制，月面可能比上述平地速度更慢。表中速度已经是实际路径速度，不能再重复乘一次地形减速。

3600s覆盖了上述.15–.30 m/s算例，并留出更多余量；若实际平均速度约.10 m/s、路径不连通或找不到可容纳四车的停车区域，仍然不足。当前不能承诺一个时限覆盖所有月面初态。启动前应在生成后的明确固定样例上检查合法出生、可用地形支撑及原规划／执行的路径与速度；这用于排除地图越界／缓存无法运行等具体缺陷和校准时限，不要求短训先学成功。

## 4. 延长时限的连带影响

| 项目 | 原1200s | 新3600s候选 |
|---|---:|---:|
| 每环境最长底层步 | 6000 | 18000 |
| 200万学习步对应满时限回合物理量 | 333.33 | 111.11 |
| 原评估日程最坏步数 | 288,000 | 864,000 |
| 最终评估预留 | 96,000 | 288,000 |
| gamma=.997下末端折扣 | .0271763 | .0000200710 |
| 只看成功+130的折扣分量 | 3.5329 | .002609 |

四车不重复计步，16个在途环境会影响实际已结束回合数。**延长回合并不增加同一物理预算下的训练量，反而减少终端样本。** 每批32×5s的序列仍为160s，GAE直接权重半衰期仍约53.1s；较长任务更依赖Critic正确bootstrap。

因此`gamma=.997`需要与3600s一起重新审定，不能只延长超时而不看信用尺度。本轮没有擅自修改奖励、gamma或lambda。作为审计备选，1s参考gamma=.999在3600s处的权重约.02727、半衰期约692.8s，接近原gamma=.997在1200s处的相对折扣；它并不同时解决GAE窗口、探索或方向问题，也尚未被选用。

沿用原初始化、50万、100万、150万、最终五个固定评估点及最终额外留出组时，评估最坏用量为864,000步。审计YAML据此将**评估上限候选改为900,000**，学习预算仍候选2,000,000。这不是新预算授权；若希望减少评估成本，应明确减少面板频率／样本数并重新计算，而不能把完整回合悄悄截成短评估或沿用不可能覆盖的30万额度。
