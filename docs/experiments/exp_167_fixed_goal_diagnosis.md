# exp167：固定局部目标的规划—执行诊断

本页保留修正前的冻结证据。用户随后批准的实现及同批复测见[规划修正记录](exp_167_planner_correction.md)；本页“下一步”是诊断当时的结论，不代表修正尚未实施。

## 目的

2026-09-18，按用户要求暂停增加网络训练，检查在原传感、通信、地形与实时限制下，合理请求能否持续转化为运动。本轮只增加诊断脚本和记录，不修改生产规划器、任务奖励、安全阈值或网络。

## 配置

- 原 `exp167_local_goal_nmpc.yaml`，4 环境、每环境 4 车、4 个规划线程。
- 原 acados 求解器，3 秒预测、0.2 秒重规划、1 秒目标刷新、0.15 秒软时限、12 次 SQP 上限。
- near Open/Mixed/修复 Bottleneck，分别使用冻结评估第一批 seed 230000/231000/232000。
- 每个闭环用例运行 12 秒。每车目标在初始里程计系固定，每秒仅重新表达为车体系请求，不随车漂移。
- 短目标来自局部观测模型中 `v=±0.2` 前进/倒车 10 步后停车的轨迹终点；先检查传感支持、轮速、变化率、邻居预测和圆盘约束。证据只针对当前模型及消息，不是全局导航或未来信息的保证。
- 转向用例在前 10 步增加 `ω=0.5`。长目标固定为本车初始前方 1.2 米：只有短前缀得到可行性检查，**不将整个未观测长路径冒称已知可行**。其用途是检查原方案承诺的“允许提前停车并逐步推进”。
- 近距停车对照仅把初始半径改为 0.6 米、jitter=0，邻车间距约 0.8485 米；仍用原地形、传感和通信，目标为保持原位。此对照不是原评估分布，也不是集合成功测试。
- 未创建策略网络、优化器或新训练 checkpoint。闭环主代码 AST hash 与上一轮 pilot 完全一致：`79283c1e97f3c42b5da89e91ffbc300318f198bd852243463289abd02848d35f`。

`tests/test_local_goal_diagnostics.py` 与 `tests/test_local_goal_nmpc.py` 共25项通过，包含真实acados回归。新增两项用于固定复现观测支持缺口及新鲜完整停车计划的末端余量冲突，不将这些测试通过解释为规划器验收通过。新增脚本静态检查及 `git diff --check` 通过。

## 严格标准

诊断只检查固定目标误差、运动与规划反馈，不替代完整任务 strict gate。位置到达按误差小于 0.1 米统计；不将已经在目标上的停车用例计入运动到达率。未来恢复训练前，还需持续运动、多车接近与完整任务层面的验证，本次不设自动续训门槛。

## 失败分析

### 1. 长目标的局部推进失效：存在可行短前缀，仍整条拒绝

在同一 16 个初始状态做冻结探针，不执行控制：每个状态都有经过检查的“前进一小段再停车”轨迹。

| 1.2 米目标设置 | 接受 / 16 | 观察 |
| --- | ---: | --- |
| 上限 0.4，原初始化 | 14 | 1 地形拒绝、1 求解失败 |
| 上限 1.15，原初始化 | 0 | 16 地形拒绝；全部返回 SQP 迭代上限状态 2 |
| 上限 1.15，用已知可行短轨迹热启动 | 1 | 15 地形拒绝，不能仅靠热启动解决 |

原细尺度最远前向采样为 0.8 米，中尺度下一采样为 1.2 米，支持半径只有 0.155 米；两者之间存在未知带。直接观测不变时，不能把该带当作自由空间。但即使允许短前缀停车，目标驱动的求解仍会尝试接近/跨越支持边界，之后整条计划被复查拒绝，车辆因而无法前进获得新观测。

这说明问题不是“必须到达 1.2 米才算成功”：当前实现没有可靠实现**长目标下只执行已知可行前缀的持续推进**。安全复查拒绝不能简单删除；规划生成和复查应共享一致的可行域。

`solver_infeasible` 目前是多个非 0/2 求解状态的统称，不是严格的数学无解证明；有可行短轨迹时仍失败，必须区分求解失败与约束集合确实为空。

### 2. 求解内部地形参数与控制复算失配

规划器把热启动轨迹位置上的坡度/通行系数写入每个时刻的参数，单次 SQP 内不会随新优化轨迹位置重新查询。输出复查却沿新控制轨迹重新查询地形。

在“已知可行短轨迹热启动＋1.15 米/秒”探针中：

- 14/16 条求解器内部节点落在圆盘支持内，但按输出控制重新 rollout 后仅 2/16 条节点仍全部在支持内。
- 内部轨迹与复算轨迹最大位置差，按用例约为 0.034–0.362 米。
- 9/16 次求解状态为 0，仍不能保证复算轨迹可接受。

因此不仅是“12 次迭代不够”：地形参数冻结位置与复核位置不一致也有直接证据。实际代理动力学偏差尚需进一步单独量化，本轮不能将全部偏差归因于真实车辆跟踪。

### 3. 停车请求与预测邻居膨胀不相容

近距停车对照中，当前距离约 0.8485 米，大于 0.42 米任务要求和 0.46 米当前规划余量。没有真实碰撞，也没有当前邻居约束违例。

但首次尚无轨迹消息时，预测末端半径达到 `0.46 + 0.15 × 3 = 0.91` 米；随后完整消息虽新鲜，携带的是上个底层周期发布的计划，新预测末端超出该计划 0.2 秒，半径约为 `0.46 + 0.08 × 3 + 1.15 × 0.2 = 0.93` 米。

当本车上限为 0 时，无法通过任何平移满足这个末端约束。12 秒内所有 192 个车辆级每秒检查都检出了末端可达区域被邻居余量完全排除，960 次规划全部回退。

这是**预测不确定余量与稳定停车的兼容问题**，不是 Actor 不会停车。并不意味着应直接缩小安全距离；应检查计划有效期、停车意图及预测尾段的约定。

### 4. 本轮未支持的归因

- 代表性训练后六层完整轨迹共 46,080 次调用，未发现请求 cap 与上一控制的 `0.3 m/s` 单步减速上限直接冲突。新增闭环也没有触发该冲突；高速用例甚至在 cap 下调之前就已被地形检查阻止。它仍是接口边界风险，但没有证据称其为此次主要原因。
- 新测试初始邻居均使用完整消息。稀疏/过期消息在更远场景下的阻塞尚未完成同等级闭环验证，不能声称通信所有分支均通过。
- 小距离前进/倒车/弧线通过，不代表大转角、反复会车或复杂绕障通过。
- 单批冻结场景不支持成功率泛化结论，也不证明 NMPC 路线应被放弃。

## 结论

基本短程执行可用，但长目标的可行前缀推进、求解/复算一致性及近距稳定停车尚未具备可靠训练条件。此次可在没有网络的情况下复现失败，不能把全部不收敛归给学习层。

## 下一步

保持网络训练暂停。先审核以下修正方向，不在本轮自动实施：

1. 统一求解、地形参数更新与连续轨迹复查，区分数值求解失败和真实不可行。
2. 明确长目标只要求可行前缀及停车尾段，防止远端未知带使整条计划反复失效；不增加全局地形访问或悄悄改成正确任务目标。
3. 统一邻居计划有效期、预测尾段及静止意图，检查任务允许的静止队形是否在规划层仍可维持。
4. 修正后先复跑同一冻结闭环，再扩展持续运动、近距离协作与稀疏消息场景；不能因简单用例通过就恢复正式网络训练。
