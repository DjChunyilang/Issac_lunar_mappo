# 奖励审计：持续扣分压过了任务结果

日期：2026-10-23，Asia/Shanghai。承接[最终训练复核](t11_final_training_review_2026-10-23.md)，按用户要求先查奖励系数与设计，再做有界算分实验。本文先解释结果，具体公式和证据放在后面。

## 1. 现在可以明确回答什么

**当前评分确实可能把“很快失败”排在“花时间完成任务”之前。** 这次不再只看回报与寿命的相关性，而是固定起点、直接调用当前奖励函数比较分数。

想象车辆从同一个远距离起点出发。一路都是平地，没有障碍，逐渐靠拢，最后停稳5秒。按当前奖励计算：

| 给奖励函数的假设过程 | 折扣总分，越高越好 |
| --- | ---: |
| 5秒时失败 | **−23.2** |
| 30秒时失败 | −115.4 |
| 300秒完成集合 | **−532.3** |
| 600秒完成集合 | −954.4 |
| 1500秒完成集合 | −1403.9 |
| 原地安全停留1500秒，但未完成任务 | −1559.6 |

**连这种没有障碍干扰的理想成功过程，都比快速失败低很多分。** 原因是车辆只要还离队友很远，就会持续扣分；等待数百秒后的成功奖励，还会受到折扣，抵不过途中扣掉的分数。

这些是**奖励层算分实验**：人为给定位置变化、成功／失败标签，调用生产奖励函数；不是新策略实际跑出了成功，也没有模拟碰撞和完整物理过程。它足以证明这组评分存在不合目标的排序，但不能证明模型已经有意识地选择失败。

## 2. 钱主要扣在哪里

对第24、81、138批保存的交互记录，提取235个从起点到结束都完整的真实回合，逐步重算并核对原始回报。下表是这些记录的平均持续扣分，不含势函数差和终端奖罚。

| 原因 | 每秒平均扣分 |
| --- | ---: |
| 距离仍远、队伍仍分散 | **3.88** |
| 地形代价 | 0.16 |
| 靠近障碍标记 | 0.15 |
| 覆盖障碍标记 | 0.81 |
| 合计，另含很小的能量项 | **约5.00** |

与之相比，地形失败只在结束时扣100，任务成功加130。简单地把“失败扣100”理解成很大的惩罚，会忽略车辆活着时每秒都在扣分。不同结果还要按时间折扣，最终排序不能只看这三个数字。

还有一项口径需要纠正：**车车碰撞的固定罚分合计是200**，包括100的终端失败项和100的碰撞项，另可能叠加间距罚分。此前对话只列出了终端项100。地形失败和越界的固定罚分仍是100，超时是80。

## 3. 真实记录也支持这个判断

235个完整回合中，有172个活过5秒。对每个回合保留完全相同的起点和前5秒轨迹，比较两种计分：

- 原记录：继续执行，之后在实际记录的时刻地形失败。
- 算分假设：第5秒就按地形失败结算，后面不再累计成本。

第二项是人为截断后的**计分反事实**，没有真的让车在第5秒撞毁，也不声称存在能实现该失败的动作。对照只回答：奖励本身是否使提前结束更划算。

结果是 **172／172 个回合都给提前失败更高分**。例如第81批、env 1、第756回合实际在31秒失败：

| 评分设置 | 假设5秒失败 | 记录中31秒失败 |
| --- | ---: | ---: |
| 当前奖励 | **−33.82** | −154.84 |
| 失败罚分从100提高到500 | **−429.23** | −526.29 |
| 仅取消距离／分散程度的持续扣分 | **−14.51** | −38.68 |
| 所有连续负成本缩小到原来的2%，事件奖罚不变 | −7.63 | **−4.18** |

整个172对样本的结果一致：前面三种设置都偏向提前失败；最后一种让后来失败的得分更高。持续成本不只是距离项，真实记录中的障碍和地形扣分也会影响排序，所以仅删除距离持续成本并不充分。

**2%只是本次敏感性测试点，没有启用到生产训练，也不是已选定的最佳系数。** 它展示了调整奖励尺度能够改变排序；是否同时损害避险、是否鼓励原地拖时间，还要靠后续真实闭环验证。只增大失败惩罚也不是当前推荐路线：在这172对样本里，达到持平需要的失败罚分为1700–2596，中位数约2077，远高于当前100。

## 4. 失败后只扣分、不结束回合，可以吗

**可以把可恢复的危险事件设计成“扣分后继续”，但不能直接把当前所有失败都改成不终止。**

先区分回合与训练：当前一次失败只结束这个环境里的当前回合。采样器会重置它、继续收集新回合，已经学到的网络权重保留。终止罚分仍会传回此前动作，结束回合本身不会阻止学习避碰。

目前已经允许一些风险发生后继续：靠近障碍、覆盖软障碍标签、车辆安全间距不足但尚未真正碰撞，都有连续扣分，并不会仅因这些软指标结束回合。

对实际碰撞和地形不可通行，当前有三个具体障碍：

1. **Proxy没有碰撞后的阻挡或反弹。** 它先按二维运动学更新位置，再检查是否碰撞。地形速度增益最低仍为0.25；没有托底、翻覆或卡住后的状态模型。直接继续可能让车辆穿过彼此或不可通行地形，不能把这种经验当作有效的碰后恢复。
2. **大额罚分目前绑在“回合结束”上。** 本次8项直接奖励调用确认：只把`ended_this_step`改成false，100的失败项和碰撞额外100都会消失。非终止事件必须有独立的事件判定和罚分，不能只关终止标志。
3. **成功口径也会变化。** 如果允许穿越严重危险后继续，最终到达可能被算成成功。需要区分“最后到达”与“全程没有严重违规的成功”，否则新成功率不能与旧结果直接比较。

因此，当前优先保留真正失败的回合终止，先修正奖励排序。若后续研究碰后退出，应先选一种可恢复事件，在现有执行层定义不会穿透、允许退离的后继状态，再把事件惩罚与回合结束分开。持续接触应按新事件和持续时间明确收费，不能每0.2秒都误算成一次新事故。真正继续时保留后继价值和记忆；真正终止时才清零尾值，相关区别可参照[Farama终止说明](https://farama.org/Gymnasium-Terminated-Truncated-Step-API)。

## 5. 系数和设计审计

生效配置取自当前run的`config/effective_configuration.json`，4个owner一致；相关生产源码SHA与run保存值一致。不是按代码默认值猜测本轮配置。

| 奖励部分 | 本轮生效参数 | 单位／作用 |
| --- | --- | --- |
| 距离、分散程度的进展势函数 | `distance_progress=9.5`、`dispersion_progress=6` | 相邻状态的折扣势差 |
| 仍然离得远的持续成本 | `distance_level=0.13`、`dispersion_level=0.04` | **每0.2秒直接扣**，并非每秒系数 |
| 平坦度 | `flatness_progress=2`、`flatness_excess=0.02` | 前者是势差，后者每步扣；只在近距区域起作用 |
| 驻留进展 | `hold_potential=12` | 势差，不能把正累计值当成实际停车成功 |
| 地形 | `terrain_weight=0.5`、`hazard_cost=0.05` | 每步扣；基础roughness/traversability/speed_loss/height_change系数为0.15／0.15／0.14／0.09 |
| 障碍 | near为0.2／秒，overlap为2／秒 | 乘0.2秒及风险强度，再取四车平均；分别最多每步0.04／0.4 |
| 车间安全距离不足 | `clearance_cost=2.4` | 每步乘不足距离 |
| 能量代理 | `energy_weight=0.003`，距离0.02、转动0.007 | 直线项乘dt，转角项未乘dt；当前量级很小 |
| 真正终端 | 成功+130；地形失败／越界−100；碰撞固定合计−200；超时−80 | 一次结算，另加当步其他分项 |
| 折扣 | 每0.2秒`0.9995193940847922` | 每秒约0.9975993；1500秒后权重约剩2.72% |

`reward_scaling=log1p`只对距离／分散程度超额取对数，**没有对总奖励做log变换或整体缩小**。系数的时间单位确实混合，当前固定0.2秒下不直接认定实现错误，但审计必须按真实尺度计算。未发现每秒gamma误用成每控制步gamma，或额外重复折扣的问题。

终端的正势差也需要澄清。所有24个同初态算分场景，势差的折扣总和都是同一个数 **95.9567**，与中途路径及结局无关。终端置零保持了这一性质，不能简单删除它。优先调整的是势差以外的持续成本与任务结果奖罚。这也符合[Ng等人的势函数奖励研究](https://people.eecs.berkeley.edu/~russell/papers/icml99-shaping.pdf)。

可复算边界：若每步持续成本固定为$c$，第$N$步失败罚$P$，首步折扣权重为1，则：

$$J_N=-\Phi(s_0)-c\frac{1-\gamma^N}{1-\gamma}-P\gamma^{N-1}.$$

在同类失败之间，延后失败得分更高需要$c<P(1-\gamma)/\gamma$。本轮$P=100$对应每步成本小于 **0.04808**，即每秒0.24042；235个完整回合实测均值约为每步 **1.00036**。这个常成本公式用于解释尺度；实际变成本排序使用逐条记录精确计算，没有用均值代替各回合。

## 6. 本轮结束条件与下一步

本轮只回答“当前奖励会不会把不希望的行为排在前面，以及能否直接取消终止”。范围固定为3个已有批次、4组参数×6种奖励假设、8项终止标志检查。原始回报可重现、排序已明确，达到结束条件，不追加物理采样或学习来重复证明这个算分问题。

下一步应只比较**一个重新平衡连续成本的奖励候选**与当前奖励，保留现有势差、真正失败终止和任务成功判据。先通过成功／提前失败／安全超时的评分排序，再在独立run做有界闭环实验，重点看安全行驶时间、实际靠拢、危险比例和成功率，不能再用总回报上升替代。候选不能把所有风险权重简单调成零，也不同时更换网络、PPO和终止语义。

这次没有选定并启用新生产系数。奖励语义改变后必须保留旧配置与checkpoint边界，不能冒充原run无缝续训。后续有学习的实验仍需实时TensorBoard和明确步数预算。
