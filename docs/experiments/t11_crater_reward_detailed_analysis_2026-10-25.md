# 百万步训练详细分析：为什么活下来了，却没有集合

日期：2026-10-25，Asia/Shanghai。承接[训练结束报告](t11_crater_reward_recovery_2026-10-24.md)。本次只分析已有记录，新增环境步、优化更新均为0，没有修改训练代码或配置。

后续进展：[目标执行对照已完成](t11_target_execution_probe_2026-10-25.md)，另计1,200诊断步、0学习更新。相同保存态中改成内向目标后2／10辆MOVE车明显推进，其余仍停滞；下一步查局部规划候选及其筛选／选择。下文保留本次只读分析及当时提出的方案。

## 先说结论

**训练正常运行，但学到的行为没有把车辆持续带向集合。问题不只是“停得太多”，也不是“失败没有扣分”。** 现有证据显示两处需要区分的断点：策略没有稳定发出朝队友靠拢的目标；部分车辆即使收到MOVE目标，规划出的动作也几乎不产生位移。长程评估中，三次撑满25分钟的回合都出现了明显停滞，最终仍相隔数百米。

因此，下一步优先做**相同保存状态下的目标执行对照**，先回答“给一个合理的靠拢目标，现有规划／控制能不能真的走过去”。若仍走不动，优先修执行链；若能走动，再处理策略目标与学习反馈。当前不建议原样追加长训，也不建议先把失败惩罚继续加大。

这次诊断的结束条件是：用现有数据区分实际行为、奖励解释和优化数值问题，并选出一个最小下一步。已达到，不继续扩大排查。

## 1. 学习曲线到底说明什么

`sample`和`mean`是同一个模型的两种动作方式：前者按学到的分布抽样，后者使用确定性动作，不是两套独立训练。下面的短窗比较使用相同4个起点；每种模式各4次。

| 看什么 | 训练前 → 训练后 | 应怎样理解 |
| --- | --- | --- |
| 60秒内失败 | sample、mean均0/4 → 0/4 | 最终短窗安全，但本轮前后没有提升空间；不表示25分钟任务安全 |
| 60秒后最远车距，sample | 平均扩大3.73 → 3.20米 | 变化很小，仍在散开 |
| 60秒后最远车距，mean | 平均扩大22.96 → 8.51米 | 扩散减轻，但还没有变成整体靠拢 |
| 10个中途评估 | 两种模式平均缩距全部为负 | 不是持续改善、只差一点收敛的走势 |
| 25分钟完整任务 | 合计0/8成功，5次地形失败、3次到期未完成 | 没有达到任务目标 |

训练首10批到末10批，已结束回合的平均原始回报35.42→54.07，平均结束时间317.98→449.56秒；这些回合不是固定起点配对，长回合跨批、未结束回合被遗漏。只能说训练记录中较晚结束的回合拿分更多，不能据此认定任务改善。固定评估比这条回报曲线更能回答“有没有学会”。

![学习诊断曲线](../../outputs/runs/upstream_1km_fixed_far/crater_reward_analysis_20261025_01/figures/learning_diagnosis.png)

图中左上是靠拢：高于0才表示缩距；右上是60秒失败率；左下是训练中选择HOLD的比例；右下是价值预测对当前批次目标的拟合程度。横轴计入此前丢弃的12,794采样步，第5批在故障前完成，保留其原实际位置。

## 2. 车辆不是完全不动，而是方向不稳定，之后容易滞留

### 短窗中，暂停更多，但朝内目标并未稳定增加

| 同4起点60秒指标 | sample训练前 → 后 | mean训练前 → 后 |
| --- | --- | --- |
| 实际平均速度 | 0.193 → 0.167 m/s | 0.315 → 0.326 m/s |
| 每车平均实际路程 | 11.60 → 10.00米 | 18.92 → 19.58米 |
| HOLD比例 | 40.63% → 48.96% | 0% → 0% |
| MOVE目标朝队友方向的比例 | 46.49% → 42.86% | 46.35% → 46.88% |

这里“朝队友方向”按目标向量与合法通信队友中心方向的内积判断，按有效MOVE时长加权；这几个面板的MOVE全部有合法参照。它描述**目标方向**，不等于真实行驶方向，也没有证明某一条直线可安全通过。

sample越来越常停，mean在这些面板中一直选择MOVE，但mean仍整体散开。因此，“禁止停车”或“让车更快”不足以解决集合问题。训练批次的HOLD均值也从36.92%升到43.89%；它与上述固定评估不是同一个统计样本。

### 完整任务中出现了持续数分钟的停滞

三次撑到1500秒的回合，最远车距都在远处基本不再变化：

| 模式／起点（从0编号） | 开始 → 最终最远车距 | 最后300秒的最远车距变化范围 |
| --- | --- | --- |
| sample／0 | 418.95 → 476.35米 | 0.144米 |
| sample／3 | 509.85 → 537.15米 | 0.153米 |
| mean／0 | 418.95 → 403.51米 | 0.0177米 |

mean／0在约300秒后就停留在403米附近；任务要求最大车距不超过12米，差距仍很大。两个sample回合还可从HOLD请求恢复稀疏真实位置：其中8辆车最后300秒的已记录位置范围均不超过0.14米，支持原地滞留，而非仅仅“队形不变、一起平移”。这些是稀疏位置，不能据此计算完整瞬时速度；mean没有同样的位置记录。

![完整行为与方向对照](../../outputs/runs/upstream_1km_fixed_far/crater_reward_analysis_20261025_01/figures/motion_behavior.png)

图中缩距同样以正值表示靠拢，曲线结束于实际失败或到期。长时间水平段说明队形没有继续改善，不代表任务已经完成。

### 发现了“发出MOVE，规划却几乎不走”的具体保存状态

只读取最终checkpoint的一个owner分片，包含4个仍活跃环境、16辆车：

- 10辆车当前收到MOVE；其中8条规划标为有效，另外2条因 `no_candidate` 进入紧急刹车。
- 8条有效MOVE的目标仍距车1.24–2.33米，但8秒预测净位移只有 **0.012–0.115米**；预测路程大于净位移，存在小幅往返／转向，不能把净位移当作路程。
- 这些车当时实际线速度绝对值均不超过0.0352 m/s。

这证明局部规划／执行中的低推进现象确实存在。`planner_valid`只表示输出有效，不保证它能有效接近目标。它是一个训练末态快照，不是8个最终评估的逐步执行日志，尚不能说明地形代价、局部最优、目标几何或请求时序中哪项造成停滞。

另发现训练日志中选中轨迹的邻车代价均值达到约1e8，而目标代价约83，值得在下一项对照中记录。但不能直接认定“过期通信把车困住”：同一个末态分片48条邻车消息全部为当前时刻，13条有代价记录的选中轨迹邻车代价全为0，低推进MOVE仍然存在。当前证据不支持把持续过期消息当成已确认主因。

## 3. 失败主要来自哪些规则，罚分有没有执行

第5–82批的471个唯一已结束回合中，400次地形失败、69次到期未完成、2次环境无效，0成功。继承的第5批只计一次，未把collection中的相同回合重复相加。

| 地形失败规则 | 回合数／400 | 当前含义 |
| --- | --- | --- |
| `driving_slope` | 336，84.0% | 接触拟合坡度或足迹任一点局部坡度超过10° |
| `impassable_footprint` | 35，8.75% | 任一足迹点地形评分低于0.25，评分含坡度与粗糙度 |
| `terrain_step` | 27，6.75% | 去除拟合坡面后，局部高差／接触残差超过0.1米 |
| `body_clearance` | 2，0.5% | 地形高出接触拟合面超过0.3米 |
| `large_crater` | 0 | 实际车身进入不可通行大坑 |

有一个坡度失败回合同时涉及两辆车，因此按车是337次、按回合是336次。当前没有记录到车间碰撞或大坑侵入终止，但不能据此证明所有未记录风险都不存在。

**这些是平面Proxy的地形几何判据，不是已经模拟出触底、翻车或掉坑。** 驾驶查询确实去掉了人工坑层，中小坑不会再直接用旧坑壁规则判驾驶失败；底图、岩石和残差保留。一般足迹检查仍使用每侧0.3米余量，只有大坑侵入单独按无余量的实际车身判定。这与既定分档范围一致。

坡度规则检查“足迹任何一点”，所以局部一个陡点也可能让整回合结束，不要求整车拟合坡度已超过10°。现有日志没保存每次触发点的地形来源，不能直接把336次坡度失败说成336次撞岩石；也不足以据此立即放宽坡度限制。

**罚分没有漏掉：400次地形失败全部记录一次−100；69次超时全部−80。** 2次环境无效没有失败罚分，对应转移被学习mask排除。最终完整评估中5次地形失败为3次坡度、2次通行度不足；其余3次活满25分钟仍未集合，说明不能把全部不集合归因于“太早失败”。

## 4. 为什么不靠拢也能拿正分

第81批保存数据中，非终端每0.2秒的实际奖励如下：

| 实际行为分组 | 平均总奖励 | 其中纯几何进展项 |
| --- | --- | --- |
| 最远车距缩小 | +0.02734 | +0.000837 |
| 最远车距扩大 | +0.02479 | −0.000944 |
| 四车全部静止 | +0.02720 | 约0 |

这些是不同状态的观察分组，不能拿这张表宣称“同一状态下停车一定比靠拢好”。它说明：**即时奖励的正负几乎不能用来判断车是否做对了事，真正的几何改善只是其中较小的一项。** 三个代表批次都出现这一现象，逐步重算 `gather` 的最大误差小于2.85e−14，未发现配置与执行算分不一致。

原因是当前集合势值为负，势差按 `gamma × 后继势 − 当前势` 计算。即使位置不变，gamma略小于1也会产生正数；奖励日志 `gather` 还混有持续距离成本。`success_hold`同样不是“成功驻留次数”：驻留没有开始时，它仍每步贡献约+0.005767；69个超时回合此项累计均约+55.249，却没有一个成功。

但不能因此直接判定奖励在鼓励失败。当前真实终端将后继势归零，完整折扣势项相加等于初态常数 `−Phi_initial`；`log1p`只处理距离／离散度输入，没有对总奖励逐步取log。同一初态、完整有效终端回合中，持续成本、事件奖罚决定不同轨迹的收益差。正的即时分数与正的回合总分，都不是策略偏好这个动作的充分证据。

实际学习信号也支持这一区分：第81批8个真实终端的GAE优势全部为负，平均−27.51；第44批4个终端也全部为负。也就是说，学习器仍把这些结束看成比它预测的继续运行更差。不能把244个地形失败回合原始总分为正解释成“失败没有惩罚”。

目前更准确的担忧是：靠拢的局部差别较小，Actor要依赖价值预测和团队共同回报辨别行动好坏；尚未证明它能稳定区分安全靠拢、停留与反向。下一步需要同状态对照，而非仅比较不同回合总分。

## 5. 是优化器没学，还是学不到任务所需的区别

现有记录不支持“优化器没有动”或“梯度被全部裁掉”：

| 每批等权统计 | 首10批（5–14） | 末10批（73–82） |
| --- | --- | --- |
| 价值预测解释方差，更新前 | 0.376 | 0.494 |
| 最后一轮日志的近似KL | 0.00143 | 0.00120 |
| 最后一轮日志的PPO裁剪比例 | 2.67% | 2.25% |
| Actor梯度裁剪 | 少量发生 | 未发生 |
| 训练HOLD比例 | 36.92% | 43.89% |

价值网络能解释当前批次目标的一部分变化，但仍有较大误差；该指标不是任务成功率。KL与裁剪说明策略发生了幅度较小的更新，不证明更新方向正确。KL／clip等取第5轮更新前的replay日志，`after_epoch`价值指标才是更新后重算；没有混称为最终参数的KL。

第82批只有240条转移，其余完整批通常512条。本表按批等权，另用第72–81批的完整末10批复核：HOLD44.20%、KL0.00125、裁剪2.26%，判断不变。

还有一个长程学习难点：完整rollout名义长度160秒，GAE直接递推权重约56秒减半；若形式上外推至300秒，系数仅约2.38%，但实际批次并不直接递推到那里，批次以外由bootstrap价值预测承接。普通奖励折扣在1500秒处约2.72%。数百米外的集合成功需要很长动作链，远期效果大量依赖价值预测。这个结构会增加学习难度，但现有数据还不能证明它是唯一根因，也不能直接据此修改gamma／lambda。

## 6. 下一步只做一个小对照

**第一阶段只回答：同一状态下，原策略目标和合理的内向目标，能否通过当前规划／控制带来真实推进？**

建议选2–4个已有“MOVE但推进极小”的保存状态，保留相同地图、车辆、规划器和随机状态，比较原策略目标与基于合法邻车信息的内向目标。第一阶段只看执行能力；内向目标本身未必可直达，需同时检查候选通路与实际地形风险。记录真实位移、目标距离变化、规划的预期进展、无候选原因和各项代价，避免只看 `valid`。

| 对照结果 | 下一步改哪里 |
| --- | --- |
| 原目标与合理内向目标都几乎不推进 | 先定位规划／控制的停滞原因，包括局部候选、代价与执行时序 |
| 内向目标能安全推进，原策略目标不能 | 优先处理策略方向选择及其动作表达／观测使用 |
| 两者都能推进，但靠拢没有得到更好的优势评价 | 再定位奖励分量、价值预测与团队信用分配 |

这个对照是诊断干预，不是把固定向内规则塞进正式策略。在本次只读分析结束时尚未执行；随后按用户授权以1,200步上限完成，详见页首后续记录，没有动用学习预算。现有分析已足够决定先做此项，不需要再全量扫描checkpoint、补旧矩阵或直接开更长训练。

第一阶段以分清执行断点为结束条件。只有确认执行可用后，才继续比较奖励与优势评价；干预轨迹上的critic数值只能作为诊断信号，不能单独证明内向动作的真实长期收益更好。
