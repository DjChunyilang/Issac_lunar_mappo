# exp133：现有连续近距项的逐车信用离线审计

## 目的

exp132 证明 \(0.42\,\mathrm m\) 最近邻成功门限能够形成非退化的逐车梯度，但只有 75% 的 rollout 出现事件，信用主要在 episode 后段激活。exp133 不新增安全模块或奖励语义，而是检验当前环境已经使用的连续近距安全项，判断它能否更早地提供逐车信用。

本实验冻结策略，只进行离线审计，不修改奖励、Actor、Critic、优化器或执行链路。

## 与现有奖励的关系

当前团队安全奖励中的连续近距项为：

\[
r_t^{\mathrm{near}}
=
-w_{\mathrm{near}}
\frac{1}{N}
\sum_{i=1}^{N}
\max\left(d_{\mathrm{near}}-m_i(s_t),0\right),
\]

其中：

\[
d_{\mathrm{near}}
=
\texttt{safety.near\_distance}
=0.72\ \mathrm{m},
\qquad
w_{\mathrm{near}}=2.4.
\]

exp133 只将该团队均值分解为车辆级势函数：

\[
\Phi_i^{\mathrm{near}}(s)
=
-\max\left(d_{\mathrm{near}}-m_i(s),0\right),
\]

\[
c_{i,t}^{\mathrm{raw}}
=
\Phi_i^{\mathrm{near}}(s_{t+1})
-
\Phi_i^{\mathrm{near}}(s_t),
\]

\[
\widetilde c_{i,t}
=
c_{i,t}^{\mathrm{raw}}
-
\frac{1}{N}\sum_{j=1}^{N}c_{j,t}^{\mathrm{raw}}.
\]

逐步中心化保证 \(\sum_i\widetilde c_{i,t}=0\)，因此团队 reward 和 Critic target 均不改变。由于 \(0.72\,\mathrm m<12\,\mathrm m\)，触发区内邻车相对位置属于现有完整通信内容；该量不要求 Oracle、全局质心或缓存外真实状态。

## 正式协议

- 配置：`exp125_decentralized_tiered_b0_pure_rl_relative_quintic.yaml`；
- checkpoint：exp125 `relative_quintic` seed23 best；
- 数据种子：`22023`、`23023`；
- 每个种子 128 个环境、512 步，即 8 段 64 步 rollout；
- 每个种子 262,144 个 Actor 样本；
- 每个种子抽取 32 个 4,096 样本梯度批次；
- 梯度抽样种子：`233`；
- 同时重建团队 PPO、exp126 地形信用和连续近距信用梯度；
- 审计前后 Actor checkpoint 摘要必须一致。

## 预注册晋级门限

只有下列条件全部满足，才允许制定一次 C3-near 4M 筛选计划：

- 两个种子的原始信用激活率均不低于 8%；
- 中心化信用激活率均不低于 10%；
- 正、负原始信用比例均不低于 1%；
- 8 段 rollout 中至少 7 段出现有效信用；
- 首次激活 rollout 的零基索引不大于 1，即最迟在前 128 步内出现；
- “环境×rollout”块的平均激活比例不低于 25%；
- 总体归一化 trace 标准差位于 \([0.90,1.10]\)；
- 近距信用/团队梯度范数中位比位于 \([0.05,20]\)；
- 地形—近距信用的负余弦批次比例不低于 20%；
- 中心化信用零和误差不超过 \(10^{-6}\)；
- Actor checkpoint 完全不变。

这些门限同时约束“总体密度”和“时间覆盖”。仅在 episode 末段出现大量近距事件，不能作为训练晋级依据。

## 停止规则

任一门限失败，则 exp133 停止，不启动 C3-near、不扫描 \(d_{\mathrm{near}}\)、权重或 trace 参数，也不改用预测冲突奖励、安全投影或在线约束。通过时也只允许先制定单一 4M 对照，不自动授权正式训练。

## 正式结果

每个种子均形成 262,144 个 Actor 样本和 32 个梯度批次。结果如下：

| 指标 | seed22023 | seed23023 | 门限 |
| --- | ---: | ---: | ---: |
| 原始信用激活率 | 17.540% | 16.704% | \(\ge8\%\) |
| 中心化信用激活率 | 25.633% | 24.966% | \(\ge10\%\) |
| 正信用比例 | 3.656% | 3.712% | \(\ge1\%\) |
| 负信用比例 | 13.883% | 12.992% | \(\ge1\%\) |
| 激活 rollout 比例 | 75.0% | 87.5% | \(\ge87.5\%\) |
| 首次激活 rollout 索引 | 2 | 1 | \(\le1\) |
| 环境×rollout 平均激活率 | 43.945% | 42.578% | \(\ge25\%\) |
| 总体 trace 标准差 | 0.8660 | 0.9354 | \([0.90,1.10]\) |
| 近距/团队梯度范数中位比 | 0.6278 | 0.7907 | \([0.05,20]\) |
| 地形—近距负余弦批次比例 | 71.875% | 46.875% | \(\ge20\%\) |
| 零和误差 | 0 | 0 | \(\le10^{-6}\) |

seed22023 的八段“环境×rollout”激活率依次为：

```text
0.000, 0.000, 0.297, 0.875, 0.742, 0.445, 0.477, 0.680
```

seed23023 对应为：

```text
0.000, 0.008, 0.391, 0.906, 0.766, 0.383, 0.352, 0.602
```

因此，连续近距项显著提高了车辆接近后的信用密度，但没有稳定地提前首次激活时间。seed22023 的前两个 rollout 仍完全没有近距事件，导致激活 rollout 比例、首次激活索引和总体 trace 标准差三个门限失败。其他预注册条件全部通过，Actor checkpoint 摘要保持不变。

## 结论

exp133 状态为 `stop_safety_credit_candidate`。不启动 C3-near、不调整 `near_distance`、权重或 trace。该结果表明问题并非“连续近距信用样本不足”，而是该信用不能稳定地在 episode 早期 rollout 激活；这一时间覆盖门限本身不能证明它晚于真实碰撞。

后续 exp134 因而离线测量 `0.72 m` 近距信用相对于预测冲突和实际碰撞的提前量。无论该诊断结果如何，都不通过继续放宽距离来扩大队形排斥范围。
