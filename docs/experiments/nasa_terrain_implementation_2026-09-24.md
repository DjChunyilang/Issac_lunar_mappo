## 数据与处理结论

官方NPB母图、LDEC采样数量及总高程误差图均已下载、记录SHA256并设为只读。母图为4000×4000、5米格距、20×20千米，南极立体投影、月球球半径1737400米。此前JPL的200×200示例与母图原生窗口`[400,2400,200,200]`逐像元完全一致，最大差0米。

16,000,000个DEM像元均有效，但15,692,234个像元的LDEC为0，即约98.08%没有落在该格中的激光回波。NASA产品已包含上游插值，不能把“有效DEM”解释为“每格独立实测”。误差图是总高程RMS，不能直接变成独立像元高斯扰动。产品定义见[NASA官方说明](https://pgda.gsfc.nasa.gov/data/LOLA_5mpp/README)与[数据入口](https://pgda.gsfc.nasa.gov/products/78)。

`configs/terrain/nasa_lola_discovery_v1.json`登记27个产品目录（含版本条目），未下载其他区域的完整产品或100份克隆；这些目录的地理边界尚未在本轮验证，不能计作27个独立区域。

已生成三个不可覆盖的地图包：

| 地图 | 范围与原生格距 | 处理网格 | 用途 |
| --- | --- | --- | --- |
| `npb_200m_real_base` | NPB `[480,2480,40,40]`，200×200米，原生5米 | 0.2米 | 基础表示及执行检查 |
| `npb_200m_hypothesis` | 与基础地图完全相同 | 0.2米 | 合成细节机制诊断 |
| `lupex_lp1_200m_real_base` | LP1 `[364,907,200,200]`，200×200米，原生1米 | 0.2米 | 第二种真实数据产品接入检查 |

这些窗口为工程检查样本，不代表覆盖整个区域的正式训练集。保留原始高程基准、可逆局部坐标、源文件哈希、质量图、有效掩码、原生/处理格距和分析基线。双线性插值采用严格支撑条件，缺值不补成平地；质量值只作源属性采样，不宣称经过误差传播。LP1的不确定性保留SfS光度敏感性含义，不与LOLA RMS合并解释。

NPB源尺度坡度/粗糙度基线为20米，LP1为4米；仿真表面指标基线为0.8米。后者只描述重采样或增强后的数值表面，不证明真实0.8米尺度细节已知。有效测量分辨率仍明确标为未知。

## 增强的实现及边界

独立实现经典diamond-square高频残差、连续有限的多项式坑形和椭球上半部岩石高度包络；没有直接复制LuNaSynth代码，也不是NASA2019未公开生成器的复现。采用[NASA论文](https://ntrs.nasa.gov/citations/20190027571)的真实基底加未解析细节思路，所有地域参数明确标为假设。

本诊断版本接受73个坑和140个岩石；仅按缺值/边界排除并记录原因，不按坡度删除困难地形。原始底图、各类残差及实例目录分别保留。岩石高度包络直接进入同一个proxy高度场；尚无独立视觉网格、刚体接触或PhysX验证。

增强残差RMS为0.02622米，最大绝对值0.36976米。按面积平均回到原生5米网格后，残差RMS为0.005587米、最大绝对值0.02260米，说明增强并非严格零低频变化；已量化记录，不能描述成“大尺度完全不变”。尚未完成地域坑石统计校准、频谱各向异性或退化形态验证，不建议据此宣称真实厘米级泛化。

## 环境与信息接口

- 新地图格式为`lunar_training_terrain_v2`，观测为`ego_v12_lunar_multiscale`；局部112点采用高度、风险、有效性三通道，基础Actor输入407维，exp167追加反馈后522维。本配置Critic分别为1398/1438维。
- 地图缓存按场景共享，环境只保存场景ID。加载/换入位于reset或显式预取阶段；查询不读文件。当前采用逐场景分组查询，不宣称无CPU/GPU同步开销。
- 数据越界/缺失不会通过平坦度检查；路径触及无效支撑时停止移动并标记数据无效截断。高风险阻挡与数据未知分开记录。这里只检查离散中心路径，不能替代车体接触和连续碰撞证明。
- Actor仍只取得局部模拟传感及合法通信；质量全图和后端不暴露给规划器。局部记忆过滤无效样本及不受邻点支持的梯度；缓存分辨率不提升测量可信度。
- exp167保留CPU上的acados求解器及host状态，`policy_device`和`raster_device`可单独指定。GPU查询会把批量结果回传CPU，因此它是混合路线，不是全GPU NMPC。
- 新版策略卷积支持3通道，旧版默认2通道；快照保存地图哈希/观测契约，不序列化共享地图张量，恢复时检查语义和内容一致。旧训练入口明确拒绝新地图，防止进入旧合成评估或静默加载旧checkpoint。

## 软件与资源验证

`.venv_terrain_cuda`已独立安装Python3.12、PyTorch2.10.0+cu126及GIS/acados接口，依赖检查通过，编译架构包含`sm_75`。原`.venv_isaaclab`仍为CPU版本，依赖检查通过；版本锁定清单保存在本run的`config/cuda_freeze.txt`。

**当前GPU阻塞**：PCI仍可识别RTX2060，但当前`7.0.0-31-generic`内核没有可用NVIDIA模块，`modinfo nvidia`报找不到模块，`/dev/nvidia*`不存在，`nvidia-smi`与CUDA初始化失败。本轮未改驱动、内核或系统启动设置。9月23日可行性报告中的GPU内核探针是此前环境的结果，不能替代本轮验收。

## 回归结果

最终全仓检查：**792通过、2跳过、6失败**。6项失败均为已有exp156配对配置引用的历史outputs缺失；2项跳过均因为CUDA不可见。新地图14项测试中13通过、1项GPU一致性跳过，真实acados测试通过。首次回归发现的旧v11 Critic维度变化已修复并经最终全仓复测验证。不能宣称全仓全绿或GPU已验收。

增强地图另完成1环境真实NMPC无学习检查和快照恢复，步进p50约115.25ms；未以成功率选取增强参数。

## 地理划分与任务参数提案

NPB与LUPEX六区投影定义一致、包围盒不相交。保持GR1/GR2和MP1/MP2的保守处理组，形成5个跨源组：NPB、CR1、GR1+GR2、LP1、MP1+MP2。新版清单不覆盖旧四组清单；NPB固定为开发数据，LUPEX四组轮流留组测试，下一组验证，其余开发。LP1地图演示对应`heldout_lupex_cr1`的开发侧。

所有同地裁剪、不同分辨率及增强应继承父区域分组。绝对配准误差尚未独立测量；不同区域仍可能共享参考产品误差。LUPEX已做描述性审计，因此这些是地理留出组，不称为从未查看过的数据。尚未开启方法调优，正式开始后只能用各折开发侧拟合参数。

| 参数 | 本轮处理 | 正式训练前需要 |
| --- | --- | --- |
| 场地 | 200米工程窗口，不缩放真实地形 | 结合完整区域相关结构、任务行驶距离设计多尺度窗口 |
| 初始间距/时限 | 8–12米生成半径、20秒诊断；不按成功率选择 | 作业目标、车辆速度及控制范围依据 |
| 平整度/车辆足迹 | 旧exp167阈值仅保留在标明用途的诊断配置 | 明确作业安全需求；DEM不足以证明接触尺度安全 |
| 处理分辨率/缓存 | 0.2米数值网格、共享缓存；不作为观测分辨率 | 根据仿真细节和GPU实测选择块大小 |
| 传感与通信 | 保留现有局部模拟传感，不自动获得全图 | 明确“仅局部信息”与“允许轨道先验”两种条件 |
| 风险/增强参数 | 显式工程假设，未从测试组拟合 | 地域统计、车辆能力或外部证据 |
| 控制器 | 保持exp167 CPU NMPC，独立设备边界 | 驱动恢复后实测GPU策略/地形查询及传输成本 |
