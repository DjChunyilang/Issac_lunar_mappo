# exp132：逐车安全势函数信用离线审计

## 目的

exp131 表明，即使阻止地形辅助梯度反对团队 PPO 主梯度，碰撞率仍达到 `0.6680`。这说明团队主梯度本身没有稳定地区分“哪辆车正在破坏最近邻安全门限”。exp132 在不修改奖励、网络、优化器和执行链路的条件下，检验现有成功门限能否形成可辨识的逐车安全信用。

本实验只进行冻结策略诊断，不启动训练。

## 信用定义

令车辆 \(i\) 到最近邻车辆的距离为 \(m_i(s)\)，并直接使用现有成功门限：

\[
d_{\mathrm{safe}}
=
\texttt{success\_thresholds.min\_pairwise\_distance}
=0.42\ \mathrm{m}.
\]

定义安全势函数：

\[
\Phi_i(s)
=
-\max\left(d_{\mathrm{safe}}-m_i(s),0\right).
\]

一步原始信用和逐车中心化信用分别为：

\[
c_{i,t}^{\mathrm{raw}}
=
\Phi_i(s_{t+1})-\Phi_i(s_t),
\]

\[
\widetilde c_{i,t}
=
c_{i,t}^{\mathrm{raw}}
-
\frac{1}{N}\sum_{j=1}^{N}c_{j,t}^{\mathrm{raw}}.
\]

因此，每个环境步均满足：

\[
\sum_{i=1}^{N}\widetilde c_{i,t}=0.
\]

该信用只描述已经存在的最近邻成功门限，不引入预测冲突阈值、方向性安全约束或新的几何超参数。中心化信用经过与 exp126 相同的折扣 trace 和联合归一化后，仅用于重建冻结 Actor 梯度。

## 审计协议

- 冻结 exp125 `relative_quintic` 的 seed23 checkpoint；
- 两个独立数据种子：`20023`、`21023`；
- 每个种子使用 128 个并行环境、512 步；
- rollout 长度为 64，共覆盖 8 段 rollout；
- 每个种子形成 262,144 个 Actor 样本；
- 随机抽取 32 个 4,096 样本梯度批次；
- 分别比较团队 PPO、安全信用和 exp126 地形信用的 Actor 梯度；
- checkpoint 参数摘要在审计前后必须完全一致。

## 预注册门限

只有以下条件全部满足，才允许制定一次 C3 训练筛选计划：

- 两个种子的原始安全信用激活比例均不低于 1%；
- 两个种子的中心化信用激活比例均不低于 1%；
- 正、负原始信用比例均不低于 0.25%；
- 归一化 trace 标准差位于 \([0.90,1.10]\)；
- 安全梯度与团队梯度的范数中位比位于 \([0.05,20]\)；
- 地形梯度与安全梯度的负余弦批次比例均不低于 20%；
- 逐步中心化信用的零和误差不超过 \(10^{-6}\)；
- 冻结 Actor checkpoint 保持不变。

最后一项梯度冲突门限用于确认地形与安全目标确实需要显式处理，而不是默认继续叠加信用项。任一条件失败，停止该候选，不训练 C3，也不改为在线预测冲突奖励或安全投影。

## 正式结果

每个种子均形成 262,144 个 Actor 样本和 32 个梯度批次。除总体 trace 标准差外，其余预注册条件全部满足：

| 指标 | seed20023 | seed21023 | 门限 |
| --- | ---: | ---: | ---: |
| 原始信用激活率 | 4.174% | 4.090% | \(\ge1\%\) |
| 中心化信用激活率 | 7.677% | 7.680% | \(\ge1\%\) |
| 正信用比例 | 0.922% | 0.923% | \(\ge0.25\%\) |
| 负信用比例 | 3.252% | 3.167% | \(\ge0.25\%\) |
| 有安全事件的 rollout 比例 | 75% | 75% | 描述量 |
| 总体 trace 标准差 | 0.8660 | 0.8660 | \([0.90,1.10]\) |
| 安全/团队梯度范数中位比 | 0.6083 | 0.5443 | \([0.05,20]\) |
| 地形—安全负余弦批次比例 | 46.875% | 59.375% | \(\ge20\%\) |
| 零和误差 | 0 | 0 | \(\le10^{-6}\) |

总体 trace 标准差 `0.8660` 与 8 段 rollout 中只有 6 段出现安全事件一致：有事件的段经过联合归一化，无事件的前段保持全零。因此该结果不是 NaN 或梯度消失故障，而是说明 \(0.42\,\mathrm m\) 门限信用主要在 episode 后段才激活。

团队—安全梯度的负余弦比例分别为 `40.625%/43.750%`，安全梯度并非团队梯度的简单重复；Actor 参数摘要在审计前后完全一致。

## 结论

exp132 状态为 `stop_safety_credit_candidate`。尽管门限信用在后段具有非退化梯度，并且与地形信用存在显著冲突，但总体 trace 标准差没有达到预注册下界。按停止规则不制定 C3、不启动 4M，也不事后放宽门限。

该结果将问题进一步限定为“安全信号出现过晚”，而不是“安全梯度完全不存在”。后续若继续研究，应先在离线层面判断现有连续 `near_distance` 安全项能否提供更早且仍严格去中心化的车辆信用；在完成新的预注册前，不修改训练奖励或执行链路。
