# exp161：四条技术路线冻结可行性比较

更新时间：2026-08-20。

## 目的

在不启动新的长训、不生成教师动作的条件下，使用相同冻结场景分别尝试四条路线，并区分“组件成功”与“完整耦合任务成功”：

1. R1：D-STC本地候选与共同站点证书；
2. R2：HPP式队友预测与本地目标belief；
3. R3：分布式候选地图共识；
4. R4：给定共同目标后的去中心化原语优化。

## 配置

配置与入口：

```text
configs/experiment/exp161_all_routes_feasibility.yaml
scripts/audit_exp161_all_routes.py
tests/test_exp161_all_routes.py
```

R1—R3使用exp156固定的1152场景，并以near/far与Open/Mixed/Bottleneck作为六个block。R4使用5个exp155真实hold死锁状态和7个人工交叉/相向场景；12个场景才是独立重复单位，内部预测轮次和best-response sweep不作为额外样本。

## 严格标准

### R1

证书必须无伪平地、满足SE(2)和候选置换不变性，并在冲突/丢失消息下不产生split-brain。完整路线还要求所有分层具有足够候选覆盖。

### R2

为避免低估HPP，本诊断给予每车全队当前真实位姿作为乐观上界，但每车只能使用自己的本地候选。进行4轮预测—响应—重规划后，要求总体目标覆盖和目标一致率均不低于90%。两个目标相距不超过 $0.5\ \mathrm m$ 才视为相同目标。

### R3

候选摘要在实际12 m邻接图上最多洪泛3轮。要求有候选时site agreement为100%，且完整路线候选覆盖不低于90%。空候选表的一致不能计作站点成功。

### R4

在每轮中，车辆按固定公开顺序依次读取邻车已承诺原语，并在hold、倒车、原地转向和S形让行动作中做局部best response。12个场景至少90%必须在16步内安全解除冲突。该门限只证明低层死锁组件，不证明共同选址。

## 结果表

| 路线 | 主要结果 | 组件判定 | 完整耦合任务 |
| --- | --- | --- | --- |
| R1 站点证书 | 覆盖40.80%，伪证书0/470 | 条件通过 | 未通过 |
| R2 HPP目标belief | 乐观目标覆盖12.07%，共同目标一致率0 | 未通过 | 未通过 |
| R3 分布式地图共识 | digest一致100%；有证据时站点一致100%；平均1.17轮 | 条件通过 | 未通过 |
| R4 去中心化原语优化 | 12/12安全解除死锁 | 通过 | 未通过 |

R2的分层结果显示，即使Open中四车都拥有本地候选，目标仍不一致：near/far Open的完整目标覆盖为31.77%/40.63%，平均目标散布为7.02/11.72 m，共同目标一致率仍为0。Mixed和Bottleneck的四车本地候选完整覆盖为0。

R3在六个分层中都能在不超过3轮内传播完已存在的候选摘要；总体平均为1.17轮。其失败率与R1完全一致，因为共识只能传播已有证据，不能产生没有任何车辆观测到的平地。

R4的12个结果全部安全，选择结果实际使用了倒车、原地转向、S形让行和少量hold。它达到了已有联合枚举上界的12/12可解率，说明47维原语并非末段死锁的主要可控性瓶颈。

## 成功原因

### R1成功部分

- proposal中心由源车使用成功gate同构采样复核；
- 位姿误差只收缩可行域，不膨胀；
- 全签commit把消息丢失转换为“不提交”，而不是错误提交。

### R3成功部分

- 四车通信图在1152场景中均连通；
- 候选摘要是有限、可去重、可转发的离散对象；
- 所有车辆接收相同source batch后使用相同确定性选择规则。

### R4成功部分

- exp156新增的倒车、原地转向和S形让行提供了退出冲突的动作；
- 显式读取邻车已承诺动作，避免了同时动作意图不可辨识；
- 顺序best response直接优化联合几何结果，不依赖稀疏团队advantage自行发现让行关系。

## 失败原因

### R1失败原因

静态4 m局部地形覆盖不足。Open几乎总有证书，但near/far Bottleneck只有0/1.04%。正确的证书协议不能替代主动探索。

### R2失败原因

HPP能够根据队友行为调整计划，但不能从未传播的私有候选中建立共同指称。每车分别选择自己的平地时，预测越准确也只会更准确地预测四个不同目标。当前失败发生在共同候选语义之前，不应通过扩大预测网络修补。

### R3失败原因

通信一致性不是信息获取。R3在有证据时完全成功，但总体站点成功仍被40.80%的候选覆盖封顶。完整稠密共享地图还会显著扩大工程范围，而瞬时地图仍不能覆盖未观测区域。

### R4失败原因

R4假设共同目标已经给定，只解决末段。其当前审计还使用固定车辆更新顺序、近距完整状态和无随机时延；直接在线采用会从Pure RL切换为混合/优化控制路线。它不能单独解决平地发现。

## 结论

```text
complete_route_passes: []
all_coupled_task_routes_failed: true
successful_components: [R1, R3, R4]
```

没有任何单一路线完整通过，但失败已经收敛到一个明确问题：主动获取可容纳四车的平地证据。当前最有依据的组合不是继续扩大Actor，而是：

```text
任务特定主动探索
→ 稀疏候选belief
→ R3有界共识
→ R1全签commit
→ R4去中心化原语优化
```
