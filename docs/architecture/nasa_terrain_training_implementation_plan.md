## 1. 技术决策与实施边界

建议采用：**NASA公开真实DEM/已下载LUPEX → 离线地形处理及可控增强 → 带来源的地图包 → GPU批量地形查询、proxy环境与策略计算**。

1. 2019年NASA论文提供“真实大尺度地形＋分形细节＋坑石统计”的方法依据。插值用于数值表示，具体核由测试选择，不是用户预先指定的唯一方案。
2. 真实产品本身形成可训练的基础地图；NASA式细节增强形成单独版本。二者均可用于实验，不把增强细节标成实测。
3. LuNaSynth固定上游提交，按函数验证后复用；主训练链不强制依赖Blender，也不把LuNaSynth当作2019年论文的原实现。
4. GPU是后续批量查询、可向量化环境计算与策略计算的目标设备。CPU负责GIS预处理及暂不能GPU化的NMPC；不能把当前CPU安装状态固定为研究约束。
5. 保留exp167作为执行链候选。其CPU NMPC采用显式混合设备方案，不以更换控制器作为地形接入的隐含条件。
6. 高保真Isaac/PhysX作为后续独立验证项。当前硬件低于官方完整栈要求，不作为本轮地图训练接入的前置条件。
7. 不预设25米场地、0.1米处理格距、原平坦度阈值或交互预算。科学尺度由数据与任务决定；资源不足时调整分块、缓存和并行数，避免压缩真实几何。

## 3. 阶段A：固定数据源与隔离软件环境

### A1. 数据源

- 从[PGDA LOLA入口](https://pgda.gsfc.nasa.gov/products/78)先下载一个开发区域的DEM、LDEC采样数量图和总高程误差图；NPB已经用于本轮探针，明确列为开发数据。
- 核对JPL样本与官方母图的覆盖和像元值。若不一致，调查裁剪/重投影处理；不覆盖原产品。
- 登记后续NASA区域目录、坐标边界和处理来源，再依据独立覆盖选择验证/测试区域。只下载必要产品，不默认下载每区100份不确定性克隆。
- 保留LUPEX六区产品与既有审计结果，作为更细格距来源候选。不同产品的误差定义分开登记，不能把LOLA RMS误差映射成LUPEX光度敏感性。
- 检查NASA区域与LUPEX地理覆盖是否相交；同地点跨机构、跨产品、跨分辨率仍归入同一地理组。共享参考数据的关系另行记录，不把不同名称等同于独立。
- 所有原始文件记录URL、产品版本、下载时间、SHA256、CRS、单位、nodata、原生格距与误差类型。

产物：`configs/terrain/nasa_lola_sources_v1.json`、原始文件清单和跨数据源区域关系表。

### A2. 软件环境

- 保留`.venv_isaaclab`现有CPU环境作为回归参照。
- 新建独立Python3.12 CUDA环境，例如`.venv_terrain_cuda`。优先核查与现有版本接近的PyTorch2.10.0/cu126组合，安装前确认平台wheel及`sm_75`支持；完整版本写入锁定文件。
- 先验证CUDA设备识别、真实样本查询、网络前向/反向数值和`pip check`，不运行优化器更新或收集训练数据。目标环境失败则记录原因并选择官方兼容构建，不修改服务器驱动作为默认修复。
- GIS预处理仍可使用现有环境。若需要完整LuNaSynth对照，另外新建Python3.11.10/固定bpy环境；仅安装最小依赖和必要资产，不执行未经审查的系统安装脚本。
- 建议新增`requirements-terrain-cuda.txt`及显式安装入口；不复用会安装完整Isaac栈的`scripts/install_stack.sh`。

验收：原始数据可读取且来源完整；目标CUDA环境通过数值与依赖检查；现有CPU环境未受影响。完成本阶段不代表允许开始训练。

## 4. 阶段B：真实数据地图包与基础表示

### B1. 地图包

建议在`terrain_data/`新增`scene_pack.py`和数据源通用适配。每个地图包包含：

| 内容 | 约定 |
| --- | --- |
| 源文件引用 | 不可变产品ID及SHA256，允许多源 |
| 坐标 | 原CRS、投影原点、局部原点、像元中心约定与可逆变换 |
| 基础地形 | 原生DEM引用；派生heightfield采用局部高程原点，不改变物理比例 |
| 数据质量 | 有效掩码、可用误差图、误差类型及采样支持 |
| 尺度 | native spacing、processing spacing、metric baseline、effective support分别保存 |
| 增强 | 独立高频残差、坑目录、岩石实例、参数/种子与生成器版本 |
| 任务引用 | 区域ID、地理组、窗口边界、场景版本与划分，不硬编码任务阈值 |

GeoTIFF保留地理来源；训练缓存使用float32数组、掩码和JSON manifest，可按需memory-map。岩石可以保留独立实例几何及占据/高度包络，不能只生成可见模型而训练碰撞仍看不到它。

### B2. 基础转换

- 先做到原生像元读取、原位裁剪、局部坐标变换和不增强导出正确。
- 重采样显式记录核、坐标约定和nodata处理。对无效区不做静默填补；显示填补另存。
- 使用已知平面、非方形栅格、不同x/y格距、边界与空洞测试比较双线性和必要的样条候选；样条若产生不受控过冲则不用于该产品。
- 坡度、去趋势粗糙度按显式物理基线计算。真实支持尺度指标和增强后仿真表面指标分别命名。
- 先形成`real_base`版本。该版本可以接入训练，不以是否生成坑石作为接入前提。

验收：坐标正反变换、像元中心、单位、无效掩码和来源追踪通过；同一地图CPU读取与导出往返一致。不得因缺数据被当作平地或安全区域。

## 5. 阶段C：按NASA方法实现可控细节增强

建议新增`terrain_data/enhancement.py`、`configs/terrain/nasa_enhancement_v1.yaml`和`scripts/build_lunar_training_maps.py`。这是独立离线工具，不在每次环境reset时启动Blender或重建全图。

### C1. 大尺度地形与分形细节

- 按2019年论文分离低频基底与高频补充。频率分界必须写成物理尺度，依据开发区域可解析统计、产品说明和论文确定，不能按输出网格数随意选取。
- 将改进diamond-square/Catmull–Rom方案作为NASA方法候选，验证其条纹、各向异性、边界和重投影误差。仅采用对当前数据与任务有必要的部分。
- 地图支持范围内的起伏、坡度和相关结构由真实数据约束；未解析频段若无外部依据，参数标为假设并保留无增强对照。
- 保留基底、残差和最终地形，量化增强前后回到原生尺度的变化。不允许无记录地改变大坡面或已有大型陨石坑。

### C2. 陨石坑与岩石

- 坑的尺寸—频率分布、形态/退化参数，以及岩石背景和抛射物分布分别登记证据。NASA论文的原则可复用，地域参数不能直接套用其他地点。
- 已在底图中解析的坑不重复添加；没有可靠目录时，限定增强到未解析尺度并报告这一假设，避免自动改写真实大坑。
- 内部一律用米描述位置/直径/高度，在栅格边界明确转换到行列索引；覆盖1米、5米及非方形格距测试。
- 核查坑中心的有限极限、公式中半径/直径含义、边缘连续性与叠加规则。不能只将NaN替换为零。
- 重叠坑采用确定性顺序或无冲突的并行合并；输出不依赖线程调度。
- 岩石位置、旋转、埋入量和形状版本写入实例表，验证与最终地形接触；视觉网格、碰撞体和proxy风险表示必须保持一致的尺度。
- 地形随机种子、坑石种子和测量误差种子分开。LOLA误差图不能默认成为逐像元独立高斯噪声。

### C3. LuNaSynth复用策略

优先借用公式、分布实现和少量资产，而非照搬`Terrain.generate`。修复或替换硬编码格距、zoom元数据、坑中心数值问题与物理单位转换，并保留Apache-2.0归属。若需要渲染对照，则在隔离环境运行一个小场景，单独报告耗时与显存。

验收：固定输入和种子复现一致；全有效区域无NaN/Inf；坑石实测尺寸与指定物理尺寸一致；基础地形未被无记录重写；统计拟合只使用开发区域。产物标记为`real_plus_hypothesis`，不称为实测厘米地图。

## 6. 阶段D：GPU地形后端与环境接入

### D1. 统一查询接口

建议新增`terrain_data/batched.py`及显式版本`lunar_training_terrain_v2`。

- 输入：`scene_id`、局部米制坐标、所需指标基线。
- 输出：高程、两向坡度、去趋势粗糙度、有效性、质量信息及来源类型；风险/可通行判据由任务配置产生。
- 高程、特征和掩码按地图共享缓存；环境只持有场景ID与变换，不为每个环境复制整张地图。
- `grid_sample`或索引查询须正确处理像元中心、北向栅格、掩码和外部坐标。禁止默认零填充、边界夹取被误读为平地。
- 缓存换入放在reset/预取阶段，固定常驻容量并记录传输耗时；地图文件读取和逐点最小二乘不得进入GPU主步进循环。
- CPU参考实现与GPU批量实现保持同一物理语义，测试坐标边缘与空洞处的结果一致性。

### D2. 生产调用点

依次改造：

1. `gathering_env_cfg.py`：数据源、场景集、设备和特征版本。
2. `terrain_features.py`：通过后端分发，保留历史解析地形实现。
3. `gathering_env.py`：按场景reset、有效区域初始化、高程/动力学查询以及环境子集/快照生命周期。
4. `observation.py`、`state.py`：观测通道、归一化和掩码；归一化仅在开发数据拟合。
5. `reward.py`、`termination.py`及平坦度/候选筛选调用：明确新指标含义，禁止旧5通道风险语义静默套用。
6. 地形显示、导出及未来PhysX入口：引用同一个地图包与坐标约定。

全地图只供环境真值和明确允许的Critic使用。Actor默认仍通过局部传感与通信取得信息；“可用轨道先验”作为独立配置条件，不能因为GPU有地图就默认暴露给Actor。

### D3. GPU与CPU NMPC边界

设定两个独立工程验证对象，不作为两种算法效果排名：

- **GPU批量proxy后端**：地图查询、可向量化状态计算与策略张量留在GPU。先用确定性动作测试reset/step，不恢复旧算法训练。
- **exp167混合模式**：GPU负责批量特征/Actor，CPU负责现有acados NMPC。一次批量传送必要局部观测到CPU，再批量回传控制，避免每车每点同步。规划器信息权限与控制语义保持一致。

混合模式需同步修改`local_goal/environment.py`和`train_local_goal_nmpc.py`的CPU断言、`.numpy()`、张量创建、RNG保存、checkpoint和hash路径。将`policy_device`、`terrain_device`、`solver_device`分开配置，不能仅把断言删除或全局device改成cuda。

若NMPC占主要耗时，报告实测瓶颈。可调整批量与工作线程，但不在地图改造中自动更换求解器、动作接口或算法。

验收：无训练reset/step、局部信息边界、有效性传播与新旧版本隔离通过；旧checkpoint遇到新语义明确拒绝或走显式适配；不得静默复用。

## 7. 阶段E：划分冻结、任务参数与资源基准

### E1. 地理划分

- 基于源产品覆盖、重叠及处理关系先划分地理组，再采样训练窗口和增强版本。
- 已用于代码调试的NPB样本保持开发用途；不作为未见测试样本。
- LUPEX既有四组隔离清单保留为历史基准。加入NASA产品后另存新版跨源分组，不覆盖原清单。
- 组数足够时保留独立测试区；不足时留组交叉验证。相邻裁剪与不同随机增强不增加地理独立样本数。
- 数据质量排除需记录原因。坡陡、无目标平地或算法失败的场景不能无记录剔除；任务可行/不可行场景分层报告。

### E2. 任务参数冻结

以项目多车集合目标为中心，针对地图支持尺度提出场地、起始距离、传感范围、车辆足迹和时间尺度配置。区分来自地图的可解析范围与来自车辆/作业的要求；缺少车辆依据时提出明确的研究假设，不把旧阈值自动移植，也不为追求成功率放宽安全条件。

只修改接入真实地图所必需的任务参数。若需要更大研究设计调整，单独说明，不让地形接入依赖整个算法重构。

### E3. 资源测量与工程初值

以下是可调整工程起点，不是科学约束或已验证上限：

| 项目 | 初始安排 | 决策依据 |
| --- | --- | --- |
| 预处理 | 单worker，数值线程1–4 | 避免16 GB RAM下重复展开地图；再根据峰值增加 |
| 资源探针窗口 | 100/200/400米；0.1/0.05米处理网格 | 已有部分测量；最终任务与细节尺度另定 |
| GPU后端环境数 | 32→128→512，仅逐级测量 | 已通过内核规模探针，尚未通过完整训练 |
| exp167混合闭环 | 1→4→8环境，4车/环境 | CPU求解器实际耗时与p95决定是否扩大 |
| 地图缓存 | 按显存预算共享，首轮上限约1.5 GiB | 要给网络、rollout、优化器和驱动留空间 |
| GPU资源目标 | 总占用初始控制在约4.5 GiB以内 | 对6 GiB设备保留余量，可根据实测修订 |
| CPU资源目标 | 单作业RSS初始约8 GiB以内并保留系统余量 | 仅工程调度预算；不能据此压缩地形比例 |

float32地图容量可按`nx × ny × 通道数 × 4字节`估算。200米/0.1米、6通道约91.6 MiB；0.05米约366.2 MiB，尚不含掩码和其它缓存。1千米/0.05米的6通道已约8.94 GiB，不能整图放入6 GiB显存。解决办法是分块/按需加载，而不是假装地形尺寸更小。

完整基准记录：地图载入、H2D/D2H传输、查询、观测、动力学、通信、Actor/Critic、NMPC各段耗时，p50/p95、RSS、显存allocated/reserved及设备总占用。区分环境步、联合四车步和单车步，避免吞吐口径混淆。

本轮规划实施范围内先做无学习闭环；反向传播可用固定诊断张量测峰值且不更新参数。正式rollout更新与短训需要解除训练暂停后执行。

验收：真实地图完整执行链没有越界/掩码误判或OOM；明确CPU/GPU/混合模式的适用批量与瓶颈。不以单项查询加速或短目标到达声称任务成功。

## 8. 后续训练比较协议（本轮不执行）

前述阶段通过后，提交训练就绪报告和预算供审核。建议比较：

1. 真实DEM基础地图训练。
2. 相同真实DEM、带NASA式细节增强训练。
3. 只用开发区统计校准的合成地图训练，作为地形来源对照。

三者保持已冻结任务、车辆、信息条件、控制器和算法一致；增强开关以外的变化要单独消融。历史纯随机任务单列，不跨任务直接排名。

测试同时保留未增强真实底图与已声明的增强假设条件，按地理组报告结果、失败原因、质量分层和增强敏感性。缺少厘米实测真值时，不声称证明了真实月面车辆接触尺度泛化。

预算根据阶段E完整执行吞吐提出，并同时报告交互量和墙钟时间；不自动沿用旧90万/10万步或以GPU批量数承诺收敛。正式训练前需明确批准恢复训练与预算。

## 9. 输出、回归与停止条件

数据产物继续放在`outputs/runs/lunar_terrain_validation/<run_id>/`，跨run源文件可放`_suite/data/`；配置/源码/中文报告进入仓库，地图、缓存、渲染和指标留在ignored outputs。

新增的核心验证覆盖：单位与方向、非方形地图、多格距、坑中心/重叠、无效边界、可复现种子、增强来源、CPU/GPU一致性、缓存共享与换入、地理泄漏、观测权限及checkpoint版本。使用现有回归测试，记录已知的exp156旧配置缺失失败，不将其混入新增失败。

分阶段停止条件：

- 坐标或物理尺度不正确：停在地图处理，不接入训练。
- 无效区域被当作平地：停在查询/观测接口。
- 增强没有依据：保留`real_base`推进，增强留作显式假设，不阻塞整个接入。
- LuNaSynth局部功能无法可靠修复：保留通过验证的独立实现与方法说明，不强制安装完整渲染链。
- 内存/显存不足：优先减少常驻地图、降低并行批量或按块处理；不改变真实尺寸。
- NMPC拖慢GPU路线：报告混合执行瓶颈，不自动换算法。
- 完整链路或任务条件尚未冻结：继续暂停学习训练。

最终交付：可追溯地图库、基础/增强地图包、GPU与CPU参考查询接口、环境接入与回归结果、资源报告、冻结的数据划分及任务配置、待批准训练协议。审核本规划后先执行A—E；训练阶段仍需单独明确授权。
