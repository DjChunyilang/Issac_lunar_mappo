## 使用方式

将下方“可直接复制的完整提示词”整体粘贴给 `ppt-master`。如果制作环境不能直接读取仓库路径，请同时上传“素材清单”中的图片和 JSON；不要让工具用网络图片或自行生成的数据替代项目素材。

## 可直接复制的完整提示词

```
你是一名擅长科研技术汇报、控制系统图解和强化学习可视化的 PPT 设计师。请基于以下约束，制作一套“多月球车自组织集合与局部参考轨迹规划”技术方案汇报。

一、交付要求

1. 只生成 10 页正文，不生成封面、目录、致谢、总结或 Q&A 页。
2. 输出 16:9、简体中文、可编辑 PPTX；图形、箭头、图标、表格和公式优先使用 PPT 原生对象。
3. 为每页写 90–130 秒的中文讲稿备注。备注负责解释术语、公式含义和方法选择理由，正文不堆细节。
4. 总汇报时长控制在 18–25 分钟，约 80% 内容用于技术路线、方法原理和技术细节，第 10 页才集中汇报最近一周进度。
5. 每页只表达一个核心结论；正文不超过 4 个短文本块，约 70% 版面用于示意图、流程图、公式或数据图。
6. 不新增实验结果章节，不按时间流水账罗列实验。实验数字只作为“为什么选择或改变路线”的证据。
7. PPT 页面中不生成任何来源页脚、引用路径或可见实验编号。实验编号和完整来源仅用于制作核对，必要时放入讲稿备注，不出现在页面画布中。
8. 文件建议命名为：
   `多月球车自组织集合_技术方案汇报_10页.pptx`

二、受众与叙事方式

- 受众是略懂强化学习、但不熟悉 MAPPO 工程细节的导师。
- 叙事顺序必须是：
  “任务假设 → 为什么选混合路线 → MAPPO 如何协同 → 训练与验证如何分层 → 策略看什么 → 策略输出如何执行 → 如何选集合地点 → 如何形成安全队形 → 如何训练和验收 → 最近一周结论”。
- 第一次出现缩写时给出中文直觉：
  - MAPPO：多智能体近端策略优化；
  - CTDE：集中训练、分散执行；
  - BC：行为克隆；
  - Proxy：用于高吞吐训练的简化代理环境。
- 不把“oracle”翻译成万能真值。统一表述为“仅在训练或评估中可用的特权信息”。
- 不把“集合点可行”说成“任务成功”；只有车队实际到达并持续满足五项条件才算成功。

三、整体视觉规范

- 主题：纯白底学术技术汇报，克制、清晰、留白充足，不做商业宣传风。
- 所有页面背景固定为纯白色 `#FFFFFF`，不得使用深色、渐变、纹理或大面积色块作为页面背景。
- 主文字使用近黑色 `#111827`，次文字使用深灰色 `#4B5563`，辅助边框使用浅灰色 `#D1D5DB`。
- 信息卡片优先使用白色填充、浅灰细边框和极轻阴影；允许局部使用不超过 10% 面积的浅色强调底，但不得破坏纯白页面观感。
- 固定颜色语义：
  - 蓝色 `#2563EB`：观测、信息流、训练流；
  - 橙色 `#D97706`：规划、轨迹与控制；
  - 绿色 `#16A34A`：通过、可行、安全；
  - 红色 `#DC2626`：失败、碰撞、未达门槛；
  - 紫色 `#7C3AED`：oracle、Critic 的训练期特权信息。
- 同一概念全篇保持相同图标、颜色和名称。
- 标题 28–32 pt，正文 18–22 pt，图中标注不小于 14 pt。
- 避免大段文字、密集英文训练曲线、3D 饼图、装饰性仪表盘和无意义图标。
- 不设置顶部色带、底部色带、来源栏或深色页眉页脚；如自动生成页码，仅使用右下角浅灰小号数字。
- 第 1、7 页将项目生成的 proxy 地形图放在带白色边距的内容区中，不得整页铺底；同时明确标注“代理环境生成地形，非实测月面数据”。
- 其余页面以原生矢量图为主。需要数据图时，依据给定 JSON 重新绘制中文简图，不直接截图 JSON 或 TensorBoard。
- 公式必须是可编辑公式对象，不要转成位图。
- 若无法读取某个素材路径，保留带文件名的图片占位框；不得自行从网络找月球图片冒充项目环境。

四、逐页制作说明

第 1 页

标题：
“任务不是让四辆车简单靠近，而是在未知月面形成安全、可停驻的集合”

本页唯一结论：
几何靠拢只是中间过程，最终目标是四车在实际平整区域内形成紧凑、低速且无碰撞的可停驻队形。

版式：
- 左侧约 68%：使用真实 proxy 地形高程图作俯视底图，在其上用 4 个同色不同编号的月球车图标标出分散初态。
- 在地形上标出：危险坑洼、候选平整区域、规划参考点、四条不同颜色的示意路径、最终四车队形。
- 用一个小图例说明：整张俯视图是“讲解用环境全局视图”，不代表 Actor 能看到完整地图。
- 右侧约 32%：用五个紧凑图标列出成功条件：
  1. 队形足够紧凑；
  2. 全车低速稳定；
  3. 保持最小安全间距；
  4. 实际车队质心区域平整；
  5. 条件连续保持 8 步。

正文短句：
- “对象：4 辆同构月球车”
- “输入：局部地形、车体状态与邻车信息”
- “不依赖人工指定的世界坐标终点”
- “第一阶段不考虑机械拼接，先解决自主集合与局部轨迹规划”

视觉重点：
从“4 个初始点”汇聚到“平整区域上的四车队形”，不要画成四车重叠在同一点。

讲稿备注必须解释：
- 最初假设为何先不研究机械拼接；
- “未知月面”意味着策略执行时不依赖完整全局地形；
- 成功判据为什么必须包含实际平整度与持续低速。

第 2 页

标题：
“采用‘多智能体强化学习 + 确定性规划控制’的混合方案，是为了兼顾协同能力与可执行性”

本页唯一结论：
把需要适应和协同的决策交给学习，把可验证的几何、轨迹、控制和安全约束交给确定性模块。

版式：
- 上半页：四列方案权衡图，不要做密集表格。每列只保留“优势、关键短板”两行。
  1. 集中式全局规划：可解释；但依赖完整地图与持续集中通信。
  2. 经典一致性控制：稳定简单；但难以处理非凸地形与可行集合区选择。
  3. 端到端强化学习：适应性强；但探索空间大、样本效率低、执行与安全难保证。
  4. 当前混合路线：学习协同 + 显式搜索/控制/安全；用亮色边框高亮为选择项。
- 下半页：从左到右画五层系统链：
  “局部结构化观测”
  →“MAPPO 协同决策”
  →“地形可行点与对称槽位”
  →“轨迹/控制/方向安全”
  →“严格评估与 PhysX 验证”。

正文短句：
- “学习模块处理多车相互影响与不确定性”
- “规划模块显式解决在哪里集合”
- “控制与安全层保证局部动作可执行”
- “高保真验证与高吞吐训练解耦”

讲稿备注必须解释：
- 为什么单纯几何中点或一致性控制不能保证地面平整；
- 为什么不让神经网络直接输出轮速；
- 混合路线的核心不是模块越多越好，而是把可验证约束留在显式模块中。

标题：
“MAPPO 相当于‘中央教练训练、四个共享驾驶员执行’”

本页唯一结论：
训练时利用团队全局信息降低学习难度，部署时每辆车仍只依赖可部署观测；同构车辆共享一套 Actor 参数。

- 紫色虚线把团队状态和 oracle 信息送入 Critic；在图上标注“仅训练期”。
- 用竖向分隔线区分：
  左侧“训练：Actor + centralized Critic”
  与右侧“执行：仅共享 Actor”。
- 底部只保留一条 PPO clipped objective：

  L_clip(θ) = E_t [
    min(
      r_t(θ) Â_t,
      clip(r_t(θ), 1-ε, 1+ε) Â_t

  ]

- 公式旁只放一句解释：“限制单次策略更新幅度，避免学习一步走得过远。”

正文短句：
- “Actor：根据当前观测决定下一步”
- “Critic：训练时评估团队整体局势”
- “四车同构，因此共享 Actor 参数”
- “部署时不需要 Critic，也不读取训练期 oracle”

第 4 页

标题：
“Proxy 训练与 PhysX 验证分层，分别解决采样效率和物理真实性”

本页唯一结论：
Proxy 用于快速学习和筛选，PhysX 用于低频高保真验证；两者回答的问题不同，不能互相替代。

版式：
- 绘制三层横向泳道：
  1. 蓝色“Torch 向量化 Proxy training”
     - 大批量并行环境；
     - 快速采样、奖励调试、消融实验；
     - 输出 policy checkpoint。
  2. 蓝绿相间“独立 Strict proxy gate”
     - 固定 96 s / 480 steps；
     - 独立评估种子；
     - 四项 strict 指标；
     - 未通过则回到训练。
  3. 橙色“Isaac Sim / PhysX / Jackal validation”
     - 轮式跟踪、三维地形 mesh、姿态和执行链路；
     - 低频、成本高。
- 第 1→2 层用实线。
- 第 2→3 层画“通过后才进入”的门。
- 在 policy checkpoint 到 PhysX 的路径上使用醒目的虚线断桥，并标注：
  “当前 policy-to-PhysX bridge 尚未接通”。
- 右下角放“能证明 / 不能证明”小卡片：
  - Proxy 能证明：策略接口、协同逻辑、统计指标；
  - Proxy 不能证明：轮壤接触、滑移、悬架、低重力真实性。

正文短句：
- “高吞吐 Proxy 负责训练”
- “独立 Proxy 负责严格筛选”
- “PhysX 负责高保真失效分析”
- “当前 PhysX 是参考轨迹跟踪基础设施，不是策略闭环验证结果”

讲稿备注必须明确：
- 初始设想曾希望直接在 Isaac/PhysX 中训练，工程上改为分层路线的原因是采样吞吐与调试成本；
- 当前 Proxy 是 2D/2.5D 简化运动学环境；
- 当前 PhysX 脚本生成预设参考轨迹并由传统控制器跟踪，尚未真正加载 policy checkpoint；
- 不得宣称已经验证真实月球车动力学。

第 5 页

标题：
“Actor 与 Critic 使用不同信息，是系统保持可部署性的关键”

本页唯一结论：
Actor 只获得执行期可提供的信息，Critic 才在训练时使用团队全局状态和 oracle；两者维度和职责不同。

版式：
- 左侧蓝色大卡片“当前主候选 Actor observation：89D”，画成五段可视化向量：
  - 10D Ego：自身运动与姿态相关状态；
  - 21D Neighbors：3 辆邻车 × 7D；
  - 50D Terrain：车体系 `5×5×2` 局部网格；
  - 5D Aggregation：团队局部聚合特征；
  - 3D Assigned slot goal：车体系槽位 `Δx, Δy, distance`。
- 右侧紫色大卡片“Centralized Critic state：54D”，画成四段：
  - 32D 全部车辆状态；
  - 8D 团队统计；
  - 5D 地形摘要；
  - 9D oracle / 训练期诊断。
- 中间画一道“部署信息边界”：
  - 可见：自身、邻车、局部地形、派生后的专属槽位目标；
  - 不可见：原始 `p*`、搜索分数、可行性、平整度诊断。
- 底部用一个橙色小注解释：
  “当前 `communication_radius=0` 在代码中表示所有其他车辆可见，即暂时不限制通信半径，不是 0 米通信。”

正文短句：
- “Actor：89D，可部署信息”
- “Critic：54D，训练期全局评价”
- “Actor 不看原始 oracle 点”
- “Actor 只接收由规划层派生的车体系槽位目标”

讲稿备注必须解释：
- 为什么地形用结构化网格而不是摄像头图像；
- 为什么给 Actor 一个局部槽位目标不等于泄露完整 oracle；
- 当前无限通信语义是阶段性工程假设，不能表述为已解决受限通信问题；
- 当前主候选采用 89D `ego_v6_gather_slot_goal`；代码默认 schema 仍为 86D，不要把 89D 写成所有配置的固定接口；
- 当前 proxy 中的槽位目标由模拟器 terrain-aware 搜索层产生，真实部署仍需要由上游建图/搜索模块提供等价局部目标；
- 当前主候选网络是 branched Actor 与 structured Critic，但网络层数不放正文。

第 6 页

标题：
“策略只输出二维局部子目标，复杂运动交给确定性执行链”

本页唯一结论：
低维动作减少强化学习探索难度，同时把轨迹连续性、转向限制与安全约束交给可检查的执行模块。

版式：
- 左上角画极坐标动作示意：车头方向为 0，扇形表示允许转角，半径表示前视距离。
- 在示意图旁放公式：

  ρ = ((u_1 + 1) / 2) ρ_max
  β = u_2 β_max

  并标注：
  `u ∈ [-1,1]^2`，当前 `ρ_max=1.6 m`，`β_max=π/3`。

- 页面中部绘制一条橙色主流程：
  `[ρ, β]`
  → `车体系局部子目标`
  → `quintic 局部 waypoint`
  → `比例跟踪控制`
  → `方向性 safety projection`
  → `bicycle proxy 推进`
- 每个模块下只放一个动词：
  “选方向 / 生成平滑参考 / 追踪近期点 / 抑制接近碰撞 / 更新位姿”。
- 右下角放“当前边界”卡片：
  - 控制器只跟踪近期 waypoint；
  - Proxy 不含质量、轮壤、滑移、悬架和低重力接触。

正文短句：
- “策略不直接输出轮速”
- “动作与底层车辆资产接口解耦”
- “轨迹和安全处理可独立检查”
- “当前仍是简化局部执行链”

讲稿备注必须解释：
- `ρ` 决定“走多远”，`β` 决定“朝哪走”；
- quintic 曲线当前离散为 12 个局部 waypoint，但控制器实际只跟踪第 2 个近期 waypoint，不能夸大为完整成熟轨迹跟踪器；
- bicycle proxy 只近似平面轮式运动，当前 wheelbase 为 `0.65 m`；
- 低维动作接口为什么便于后续替换底层 Jackal 或月球车控制接口。

第 7 页

标题：
“Terrain-aware 搜索解决‘在哪里集合’，实际质心 gate 防止虚假成功”

本页唯一结论：
先找到可行平整参考点仍不够，最终必须检查车队真实质心周围的完整集合区域。

版式：
- 左侧约 55%：在 proxy 地形图上画多分辨率搜索。
  1. `9×9` 粗搜索；
  2. 围绕最优候选做两层 `5×5` 细化；
  3. 局部无解时启用 `33×33` 全局回退；
  4. 保留 top-32 beam 再细化。
- 用绿色候选点表示可行、红色叉表示坡度或高差不合格，最终用星形标出 `p*`。
- 搜索图下放公式：

  p* = arg min_{q ∈ C, F_flat(q)=1} J(q)

  公式旁用小标签解释：
  `J(q)` 综合平均行程、最远行程、路径风险、路径高差和平整度。

- 右侧约 45%：画“37 点实际质心 footprint”。
  - 以实际团队质心为圆心；
  - 半径 `0.75 m`；
  - 中心 1 点 + 3 圈 × 12 点；
  - 标注 `height range ≤ 0.18 m`、`max gradient ≤ 0.25`。
- 中间用一条粗箭头写：
  “找到可行点 ≠ 车队实际到达”。
- 右下角放一个简洁证据卡：
  “同一旧策略：
   旧几何成功 98.83%
   → 新实际平整语义 11.04%”
  用红色下降箭头，并在证据卡内部标注“定义改变后的复评，非新旧算法公平对比”。

正文短句：
- “几何中点可能落在坑边或坡面”
- “搜索点只提供参考”
- “成功检查使用真实团队质心”
- “oracle 可行率不能替代执行成功率”

讲稿备注必须解释：
```
